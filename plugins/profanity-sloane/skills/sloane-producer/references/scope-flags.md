# Scope Flags & Red Flags — Profanity Creative

## Common Scope Creep Patterns

Flag these whenever they appear in a brief or client conversation. They almost always mean more hours.

| Pattern | What it signals | How to handle |
|---------|----------------|---------------|
| "Just one more version" | Revision creep | Remind client of rounds included; quote additional rounds |
| "Can we also do a vertical cut?" | Format creep | Flag as add-on, not included in base scope |
| "We'd love raw files too" | Deliverable creep | Flag as add-on with associated cost |
| "The product might be changing" | Asset instability | Note that scope assumes finalized assets; changes reset certain phases |
| "Can we see a few different looks?" | Concept scope inflation | Define how many directions are included upfront |
| "Our CEO wants to see it first" | Approval chain surprise | Ask about approval layers before scoping timeline |
| "We're presenting to the board next week" | Rush timeline | Rush fee applies, flag proactively |
| "Can you match this reference exactly?" | Licensing/IP risk | Flag if reference is a specific brand or proprietary style |

## Questions to Ask Before Committing to a Project

### Brief Quality
- What's the core goal of this film/visual? (Sell the product? Explain how it works? Build brand presence?)
- Who's the audience and where does this run? (Social? Broadcast? Trade show? Web?)
- Do you have existing brand guidelines, look books, or references we should align with?

### Assets & Approvals
- Do you have final 3D assets or CAD files, or will we need to model from scratch?
- Are the product designs finalized, or is there a chance things change mid-project?
- Who approves creative decisions? One person, or a committee?

### Timeline
- Is there a hard deadline? What's driving it?
- Are there internal milestones we should know about (board presentations, launch dates, trade shows)?

### Budget
- Do you have a budget range in mind? (Helps calibrate the tier proposal)
- Have you worked with a 3D studio before?

### Deliverables
- What formats do you need? Any broadcast or print specs?
- Do you need cutdowns or adaptations for different platforms?
- Do you want the source files? (Flag as add-on)

## Red-Flag Client Behaviors

These don't automatically kill a deal, but they warrant extra caution in scoping and contracting.

| Behavior | Risk | Recommended response |
|----------|------|---------------------|
| Refuses to share a budget | May be fishing or underbudgeted | Qualify early — present tiers and ask which range feels right |
| "We've had bad experiences with studios" | Unclear expectations or high-maintenance | Ask what went wrong; look for patterns |
| Wants a very tight turnaround with no flexibility | Signals internal chaos | Rush fee applies; confirm hard deadline in writing |
| Changes brief significantly after deposit | Scope instability | Change order required; document everything |
| "Can you just do a quick one?" | Undervaluing the work | Clarify scope fully; $15k floor holds |
| Multiple rounds of concept feedback before approval | Indecision | Define revision rounds in contract explicitly |
| Slow to respond during production | Can blow timeline | Build in response deadlines in the project agreement |
| "We'll handle the music ourselves" | Can create sync/delivery issues | Confirm delivery specs and timing expectations |

## Scope Ambiguity Checklist

Before sending a proposal, confirm these are answered:

- [ ] Number of hero shots or final deliverables is defined
- [ ] Product assets are confirmed (CAD, existing 3D, or model-from-scratch)
- [ ] Number of revision rounds is stated in the scope
- [ ] Timeline has been confirmed with the client, including any hard deadlines
- [ ] Delivery format and specs are defined
- [ ] Payment terms are in the proposal
- [ ] Any optional add-ons are clearly separated from the base scope
- [ ] Pricing has been confirmed with Mark before sending
